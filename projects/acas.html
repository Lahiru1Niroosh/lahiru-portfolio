The problem

Credibility checks can expose the people being checked.

Social media posts contain both content to assess and personal metadata that should not be sent through every model. ACAS was designed to route text-only, image-only and multimodal posts through a sequential assessment while masking user metadata before analysis. This was a group final-year research project at SLIIT.

Key decisions

Why I built it this way.

01

Make privacy non-skippable

The controller runs PIIAgent before the model stages so user metadata is masked before AI processing.

02

Route by available input

Text-only, image-only and multimodal posts follow applicable stages through a shared orchestration interface.

03

Keep raw and masked evidence distinct

MongoDB collections tweets_raw and pii_audit record the input and privacy transformation for review.

Measurement: This page focuses on the architecture and privacy controls. It does not report model accuracy, precision, recall or latency.

What broke

What I learned while building it.

01

Integration boundaries

Four independently developed components needed a shared controller and plug-and-play interface. The lesson was to agree one shared interface early, so each component can be swapped without rewriting the controller.

02

Audit visibility

Raw and masked records were separated to make the privacy transformation inspectable. Access controls for those records are not documented.

03

Model delivery

Large model weight files are excluded from the public repository; local reproduction requires the weights or retraining instructions.

Limitations

What this project does not claim.

This is an academic group project. The repository omits large model weights and does not publish benchmark metrics yet. Docker deployment, live social-media ingestion, multilingual support and a browser extension are listed as future work. Masked PII and raw audit records require careful access control in any real deployment.
