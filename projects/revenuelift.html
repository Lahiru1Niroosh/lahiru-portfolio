The problem

A raw p-value can push the wrong rollout.

A simulated e-commerce checkout redesign appeared to improve aggregate conversion with a raw p-value of 0.015. But the project evaluated ten significance tests. After Benjamini–Hochberg correction, the aggregate adjusted p-value was 0.050, while a mobile segment still showed a robust effect. The decision had to account for both statistical uncertainty and guardrail regressions.

Results

Ship with caveats: mobile only.

Scope and measurement matter as much as the headline numbers.

01

+35.6% mobile

Relative conversion lift in the mobile segment; adjusted p=0.003.

02

Aggregate near-miss

Raw p=0.015, adjusted p=0.050 across the ten tests in this analysis.

03

+2.9% load time

The new flow significantly worsened page load time, p < 0.0001, and needs monitoring.

Projected impact: The analysis estimates approximately $857,401 in additional annual revenue for a mobile-only rollout. It is an assumption-based projection from a simulated experiment, not realized revenue. The recommendation is to roll out to mobile, test desktop separately, and monitor speed.

What broke

What I learned while building it.

01

Aggregate result changed

Multiple-testing correction turned a tempting headline win into a statistical near-miss. The analysis changed the recommendation rather than hiding the correction.

02

Guardrail regression

Page load time worsened under treatment; the decision report calls for monitoring instead of focusing only on conversion.

03

Desktop uncertainty

The mobile effect should not be applied to desktop. A separate desktop test is the next measurement step.

Limitations

What this project does not claim.

This is a simulated experiment. The revenue projection depends on documented assumptions, and no live customer behavior or realized revenue is claimed. Adjusted p=0.050 is a boundary result whose interpretation depends on the pre-registered criterion. Desktop needs an independent test, and mobile page-speed regression needs monitoring.
