01 / My story

Reliability came first.

I started in sales and IT support, then worked as a database administrator on production Oracle systems supporting core banking. Working on the database side taught me what reliable data takes: backups that actually restore, logs you read before things break, and scripts that watch systems so people don’t have to.

My goal now is a data engineering role. I’m also interested in data analytics and the layer that turns dependable data into useful decisions. My projects show both sides: DataGuard investigates silent drift between databases, while Billing Assurance turns billing controls into dashboards people can act on.

Principles

How I approach every build.

01

Validate at the source

Bad data is cheapest to fix where it starts, so I check early.

02

Design for failure

Pipelines should restart cleanly, and backups are only real once restored.

03

Measure, then claim

I state results with how they were measured, and label simulated data.

04

Make it usable

A correct table nobody can read does not help. Output is built for the reader.
